## Drie principes (uit de site zelf)

1. **Tools die je echt kunt gebruiken.** Iedere cluster ship&apos;t
   een werkende, browser-side demo. Niets verstopt achter een
   wachtlijst.
2. **People-first writing.** Geen keyword-stuffed AI-slop. Elke pagina
   is geschreven door iemand die audio in productie heeft gestuurd en
   bereid is om in het openbaar fout te zitten.
3. **Built where it matters.** Android, realtime DSP, accessibility,
   developer-ergonomics. De plekken waar audio-AI echt moet werken,
   niet alleen marketing-demo&apos;s.

<ChalkDoodle type="arrow-curve" className="mt-12 mb-2 opacity-50" />

## Cluster-structuur

De site is opgebouwd rond drie inhoudelijke clusters, elk met een
eigen tools-, docs- en insights-stream:

| Cluster | Focus |
|---|---|
| **MixLab** | AI mastering, mix-feedback, productie-tools voor producers |
| **HearLab** | Non-medical hearing-support, accessibility-design, doelgroep-onderzoek |
| **Engineering** | Realtime DSP, AAudio, Android-audio, ontwikkelaars-ergonomie |

Daarnaast vaste pages: methodology, glossary, showcases, labs, api,
roadmap, changelog, pricing, contact, privacy. Allemaal indexable
content — geen JS-only routes.

## Stack

| Laag | Keuze |
|---|---|
| Framework | Astro 6 (content-eerst, statisch met React-eilanden waar nodig) |
| UI | React 19, Tailwind v4 (CSS-first config) |
| Inhoud | MDX (`@astrojs/mdx`), per-cluster content-collections |
| OG-cards | Satori + Resvg.js — dynamisch gegenereerd op build-tijd |
| Fonts | Geist + JetBrains Mono (variable) |
| Performance | Sharp voor image-pipeline, build-time pre-rendering |
| RSS | Feed.js per cluster, per-tag |
| Sitemap | `@astrojs/sitemap` |

Astro is gekozen boven Next.js voor deze use-case: content-eerst,
veel statische pagina&apos;s, React-eilanden voor interactieve
demo-tools alleen waar het echt nodig is. Geen 100% client-side
rendering voor een glossary.
